# Kōn-Kōn Matchā Ledger 完整中文使用手册

版本：2026-09-19  
适用范围：线上 Next.js 工作区、Vercel 部署版本和共享 Windows/Android 外壳  
读者：Owner、Admin、Manager、Accountant、Cashier 及新用户培训人员

> 本手册用于日常操作与内部控制培训。国家报告、税务数字和电子发票输出目前属于管理工作底稿，不是经认证申报或税局接受证明。

## 1. 快速开始

### 1.1 第一次登录

1. 打开公司提供的系统网址。
2. 输入个人用户名和临时密码。
3. 系统要求时立即设置新密码，不要重复使用其他网站密码。
4. 左侧是功能菜单；手机上先点击菜单按钮。
5. 页面顶部显示当前位置，底部显示公司、记账币种和时区。
6. 完成工作后从左下角退出登录。

如果看不到某个菜单，通常表示当前角色没有权限。不要借用他人账号，应让 Owner 或 Admin 检查角色。

### 1.2 五种角色

| 角色 | 主要职责 |
| --- | --- |
| Owner | 公司控制、安全设置、全部业务权限、预算批准、期间重开、附件存储和所有权 |
| Admin | 日常工作区、团队和主数据管理；不能转让所有权 |
| Manager | 柜台、销售、会员、库存、采购、审批和经营报告 |
| Accountant | 账簿、客户发票、应付、费用付款、对账、资产、预算和月结 |
| Cashier | POS、会员、优惠券、收据和只读库存 |

每人必须使用独立账号。不要共享账号，因为关键操作会记录实际操作者。

### 1.3 Owner 上线清单

按以下顺序准备系统：

1. 在 **Workspace** 设置公司名称、国家、地区格式、时区、税务显示和记账币种。
2. 在 **Locations** 建立门店和仓库，再在 **Counters** 建立收银柜台。
3. 在 **Payment methods** 建立现金、银行、DuitNow 或其他付款方式。
4. 外币采购前先设置对应汇率。
5. 在 **Team & access** 为每位员工建立独立账号和角色。
6. 如使用费用附件，由 Owner 设置私有 GitHub 仓库和具备 Contents 读写权限的细粒度 Token。
7. 建立产品、期初库存、供应商、客户和必要会计科目。
8. 用测试销售、退款、采购、收货和付款完成一次全流程演练。

记账币种在产生账簿分录后不能更改。国家、语言或时区设置不会重新标记历史金额。

## 2. 每日营运流程

### 2.1 开班

1. 进入 **Counters**，确认设备对应正确门店和柜台。
2. 清点钱箱并按实际金额开班。
3. 检查打印机、扫码器、付款显示和网络。
4. 进行一笔小额测试或检查最近成功交易。

### 2.2 POS 销售

1. 进入 **Point of sale** 并确认柜台和销售地点。
2. 搜索或扫描商品，调整数量。
3. 需要时通过姓名、电话模糊搜索、QR 或 NFC 选择会员。
4. 应用有效优惠券。
5. 核对服务器计算的价格、折扣、税和总额。
6. 选择付款方式并完成结账。
7. 打开生成的收据，打印、导出或提供安全客户链接。

不要把二维码、付款动画或本地付款通知当作银行结算证明。网络中断后先刷新 **Receipts** 检查是否已经生成交易，不要连续点击结账。

### 2.3 收据与退款

1. 在 **Receipts** 按收据号、会员或日期查找交易。
2. 打开详情检查商品、付款、税、积分和操作者。
3. 选择退款商品及数量，输入真实原因和退款方式。
4. 提交后，库存、批次、积分和会计按原销售快照一起冲回。
5. 多次部分退款时，系统会限制累计数量和金额不超过原销售。

已开出的销售不能直接重写；必须使用退款保留反向证据。实际退款仍须在支付渠道或银行记录中确认。

### 2.4 交班与日终

1. 停止该柜台的新交易。
2. 清点实际现金并填写收班金额。
3. 对任何差异填写事实说明。
4. 关闭班次。
5. Manager 检查异常退款、现金差异、未关闭班次和当日报表。

## 3. 销售与客户

### 3.1 会员

- 在 **Members** 建立会员，只保存业务真正需要的资料。
- 发放 QR/NFC 选择凭证时，完整 Token 只显示一次；遗失后撤销并重发。
- QR/NFC 只用于选择会员或员工，不是登录认证。
- 停用会员后，其选择凭证不能继续使用。
- 不要在备注中保存完整身份证、银行卡或敏感付款资料。

### 3.2 优惠券

1. 在 **Coupons** 建立代码。
2. 设置开始/结束日期、最低消费、折扣、次数和会员条件。
3. 在 POS 结账前应用并确认资格。
4. 过期或不再使用时停用，不要删除历史兑换证据。

### 3.3 客户账户与信用

1. 在 **Customer accounts** 建立客户、账期、信用额度和发票默认值。
2. 客户信用只在发票草稿变为 `SENT` 时强制检查。
3. 信用检查、状态变化和决定快照在同一交易内完成，不能通过并发发送绕过。
4. 客户 Statement 排除草稿和作废单，仅供内部对账，不证明外部收款。

### 3.4 报价、送货单与发票

1. 建立 **Quotation**，核对商品、税、金额和有效期。
2. 报价状态只能向前推进；只有 `ACCEPTED` 报价可转换为发票草稿。
3. 每个报价最多转换为一个发票草稿。
4. 需要时建立报价关联的 **Delivery order**。
5. 送货单从计划、发出到送达只代表内部操作状态，不移动库存、不记录付款，也不证明客户签收。
6. 在 **Invoices** 复核草稿后发送；需要更正时使用允许的作废或新单据流程。

## 4. 库存

### 4.1 商品主数据

在 **Inventory** 建立：

- 唯一 SKU、名称、类别和单位；
- 售价、成本和补货点；
- 是否需要批次追踪；
- 默认成本中心或项目；
- 当前是否启用。

成本会影响毛利和会计，只有授权人员可维护。产品默认维度只影响未来交易，历史快照不会改变。

### 4.2 期初库存与库存调整

- 使用受控期初库存、盘点或明确调整建立真实数量。
- 不要直接改商品数量来掩盖差异。
- 调整必须写明原因、日期和操作者。
- 归档商品前确认没有仍需销售或采购的业务；历史记录仍保留商品快照。

### 4.3 批次与效期

1. 批次商品收货时填写供应商批号和晚于收货日的效期。
2. 在 **Batch & expiry** 查看即将到期、已过期和新鲜度预测。
3. 销售按受控批次分配，不要手工绕过批次数量。
4. 退款继承原销售批次快照。

### 4.4 盘点

1. 建立 Stocktake。
2. 盘点期间减少同时收货、销售和调拨。
3. 输入实际数量并复核差异。
4. 由授权人员过账。
5. 保留差异原因和生成的库存/会计证据。

### 4.5 报废和损耗

对过期、损坏或不可销售库存使用 disposal/write-off。报废不是删除；系统保留库存减少、会计冲减、原因和操作者。

### 4.6 跨地点调拨

1. 在 **Stock transfers** 选择来源、目的地和商品。
2. 核对来源库存和批次后发出。
3. 运输期间数量保持在途。
4. 目的地按实际收到数量确认。
5. 差异或取消通过允许的状态操作处理并填写原因。

来源和目的地不能相同。不要在目的地提前销售在途库存。

## 5. 采购与应付

### 5.1 供应商

在 **Purchasing & payables** 建立供应商代码、名称、联系人、税号、国家、币种、账期、交期、最低订单和备注。历史供应商不要删除；没有未完成采购单后可归档。

系统的 **Supply Pulse** 使用到货准时率、平均延迟天数和逾期采购单提示供应风险，它是管理指标，不是对供应商的保证。

### 5.2 智能补货

补货建议综合：

- 当前库存；
- 补货点；
- 最近 30 日销量；
- 预计交期；
- 已有采购单在途数量。

在建立采购单时可选择 **Build from replenishment queue**。建议仍须人工检查季节性、促销、保质期、仓储空间和供应商能力。

### 5.3 采购申请

当门店或部门需要先获得内部批准时：

1. 打开 **Requisitions** 并建立新采购申请。
2. 选择收货地点、需求日期、优先级和可选建议供应商。
3. 填写明确业务理由、商品和数量后提交。
4. 由不同的授权人员批准或填写理由驳回；除 Owner 覆盖外，申请人不能审批自己的申请。
5. 已批准申请点击 **Create purchase order**，选择供应商并确认成本、税和预计日期。
6. 转换时系统锁定已批准的地点、商品和数量，并在同一数据库交易中标记来源申请已转换，防止重复采购单。

取消、驳回、批准和转换都会保留版本、操作者、时间和原因。采购申请本身不会移动库存、产生应付或过账会计。

### 5.4 采购单

1. 新建采购单草稿。
2. 选择供应商、收货地点和预计日期。
3. 输入供应商参考、税率、含税模式、商品、数量和单位成本。
4. 核对供应商币种、汇率和最低订单。
5. 保存草稿后由授权人员审批。除 Owner 小企业覆盖外，制单人不能审批自己的采购单。
6. 未收货的草稿或已批准单可带原因取消。

### 5.5 收货

1. 只能对 `APPROVED` 或 `PARTIALLY_RECEIVED` 采购单收货。
2. 输入本次实际到货数量，不要填写剩余预计量。
3. 输入供应商发票号、发票日期、收货日期和备注。
4. 批次商品必须填写批号和有效期。
5. 提交后，库存、加权成本、供应商表现、应付账单、总账和审计在一个数据库交易中更新。
6. 如果供应商确认剩余数量不再交付，对部分收货单使用 **Close remainder** 并填写永久原因。这个操作不会冲回已经收货的库存或账单。

### 5.6 应付账龄

打开 **Bills & payments** 查看：

- Current；
- 1–30 天；
- 31–60 天；
- 61–90 天；
- 超过 90 天；
- 未来 7 天到期；
- 总逾期敞口；
- 按供应商集中度。

点击 **Export aging CSV** 可将截至当前日期的未结账单导出给管理层或外部会计复核。

### 5.7 供应商付款

1. 选择未结账单。
2. 输入付款金额，可部分付款但不能超过余额。
3. 选择现金或银行会计科目。
4. 输入真实且唯一的银行参考号、付款日期和备注。
5. 外币账单按付款时有效汇率计算，并自动记录汇兑损益。

系统付款记录不等于银行已结算证明，必须通过银行对账确认。

## 6. 员工费用与附件

1. 员工建立费用草稿，填写日期、费用科目、金额、税和业务说明。
2. 每个草稿最多有 10 个有效附件，逐个上传。
3. 系统保留附件原始字节；只在压缩后确实更小时使用无损 Brotli，然后加密保存到 Owner 设置的私有 GitHub 仓库。
4. 单文件上限为 4 MB，以适配 Vercel Hobby 请求限制。
5. 提交后由合资格人员审核。非 Owner 不能审核自己的费用；Owner 覆盖会保留审计。
6. Accountant 或 Owner 选择付款账户、参考号和日期完成付款。

常见图片、PDF 和文本可在系统预览；浏览器不兼容的 HEIC/HEIF 可下载。预览与下载分别检查权限、完整性并写入审计。草稿附件移除不会硬删除受保护历史副本。

## 7. 会计与财务控制

### 7.1 日记账

1. 在 **Accounting** 选择日期和说明。
2. 增加借方和贷方行，合计必须相等。
3. 需要管理分析时选择有效成本中心或项目。
4. 复核期间、账户和支持资料后过账。
5. 已过账错误必须通过冲销和新分录更正，不能静默改写。

报表只读取 `POSTED` 日记账。

### 7.2 银行对账

1. 从银行下载 CSV，保留真实交易参考号。
2. 选择银行科目、对账期间、期初和期末余额。
3. 导入并验证 CSV 行及余额算术。
4. 逐项复核系统建议并人工确认；建议不会自动确认。
5. 差异为零后完成并锁定工作底稿。

这不是实时银行连接，也不证明银行结算。完成记录保存当时已清和未清项目快照。

### 7.3 月结

按月份顺序关闭：

1. 完成银行对账。
2. 检查日记账完整和平衡。
3. 复核应收、应付、库存异常和费用。
4. 过账到期账面折旧。
5. 处理所有阻止项和重要警告。
6. 关闭月份并保存快照。

关闭期间会阻止新的会计写入。只有 Owner 可按倒序重开；重开不会删除原关闭证据。

### 7.4 固定资产

1. 建立资产编号、类别、购置日期、成本、残值和使用年限。
2. 选择正式购置入账或明确的仅登记迁移。
3. 按月份顺序运行账面折旧。
4. 处置时输入日期、收入和说明。
5. 核对资产登记册和自动生成的总账分录。

账面折旧不是税务资本津贴表。

### 7.5 预算

- 预算按日历年度管理收入和费用科目。
- Accountant 或 Admin 可编辑单一草稿。
- Manager 可读取。
- 只有 Owner 可批准。
- 新批准版本会取代之前的批准版本并锁定草稿。
- Actual 只来自已过账日记账正常余额。
- 收入高于预算或费用低于预算显示为正向表现。

预算不是日记账、法定申报或保证预测。

### 7.6 成本中心与项目

- 代码是永久主身份；不再使用时归档，不删除历史。
- 手工分录与自动规则会保存代码、名称和 ObjectId 快照。
- 自动规则可对 POS 地点、采购地点或费用科目精确匹配。
- 归档维度会禁用引用它的规则。
- Dimension P&L 使用已过账收入/费用并单独显示未分配活动。

维度报告只用于管理分析，不改变总账平衡、期间锁或法定财务报表。

## 8. 报表与电子文件

### 8.1 财务和经营报表

在 **Reports** 选择期间后可查看和导出损益表、资产负债表、试算表、现金流、库存、销售和其他经营分析。导出 CSV 或打印 PDF 时记录报表期间，并从汇总数字核对来源明细。

### 8.2 国家报告

Country report desk 可准备多个国家/地区的管理工作底稿，并为 MY、SG、AU、GB 提供部分布局。它不是已认证报税表，正式使用前必须由当地合资格会计师或税务顾问复核。

### 8.3 电子发票文件

系统可准备、加密和保留 UBL XML、会计 JSON 和有限的 MyInvois 文件。目前不提供：

- 税局正式提交；
- 数字签名；
- 官方接受状态；
- 完整法定申报证明。

不要把“文件已生成”描述为“已向政府提交”。

## 9. 设置、安全与维护

### 9.1 Workspace、门店和模板

- 在 **Workspace** 管理未来交易使用的公司、地区、税务显示和联系方式。
- 在 **Locations** 管理门店、仓库和层级。
- 在 **Counters** 管理收银柜台和负责人。
- 在 **Payment methods** 管理付款类型和显示顺序。
- 在模板设计器维护收据和发票外观，先预览再用于正式单据。

### 9.2 团队安全

1. 为每人建立独立账号和最小权限角色。
2. 新账号使用临时密码并强制首次更改。
3. 员工离职立即停用；不要改名转给新人。
4. 定期复核 Owner 恢复方式、附件 Token 和所有权转移请求。
5. 不要在聊天、截图或支持工单中发送密码、数据库 URI、API Token 或 Webhook Secret。

### 9.3 审计与例外

在 **Reviews** 查看销售、库存、付款和权限异常。记录调查、负责人和解决说明后再关闭。审计日志证明系统记录到的操作者与时间，但不替代管理人员的真实复核。

### 9.4 数据保留

在 **Maintenance** 先预览保留策略的影响，再执行允许的操作数据清理。执行前先备份并记录批准。财务证据、已开单据和必要附件不会通过普通保留流程硬删除。

## 10. 常见故障

### 页面加载慢

等待当前动作完成后只刷新一次。不要连续提交付款、收货或结账。恢复后检查是否已经生成收据、账单或付款。

### Session expired

重新登录。如果频繁出现，让 Admin 检查账号是否停用、密码是否刚被重置或浏览器是否阻止 Cookie。

### 没有权限

确认用户角色和工作职责。不要使用共用管理员账号。

### 扫码或 NFC 没反应

检查浏览器/设备权限、扫描会话是否过期、凭证是否撤销，以及当前页面是否正在等待扫描。

### 附件无法查看

先尝试下载。如果下载也失败，向 Owner 提供费用编号、文件名、时间和页面错误，不要提供 GitHub Token。HEIC/HEIF 可能只能下载。

### 数据库或部署错误

记录发生时间、页面、单据编号和安全的错误信息。不要复制数据库 URI 或环境变量给普通支持人员。

## 11. 培训检查清单

新用户应在测试环境或测试资料上完成：

- 登录、修改密码和退出；
- 找到与角色对应的菜单；
- 开班、完成销售、找收据和关闭班次；
- 搜索会员并说明 QR/NFC 不是登录；
- 说明退款与直接修改的区别；
- 查看库存与批次；
- Manager 完成采购单、审批、部分收货和短收关闭；
- Accountant 查看应付账龄、付款、日记账、银行对账和月结；
- 上传、预览和下载费用附件；
- 导出一份 CSV 并打印一份 PDF；
- 说出系统不能证明的五件事：银行结算、客户签收、税局接受、认证申报和税务资本津贴。

## 12. 获取支持时应提供

- 页面或模块名称；
- 单据编号；
- 发生日期和本地时间；
- 执行了什么操作；
- 页面显示的安全错误文字；
- 是否刷新后重复；
- 浏览器和设备类型。

永远不要提供密码、Session Cookie、数据库凭证、GitHub Token、Webhook Secret 或完整敏感付款资料。
